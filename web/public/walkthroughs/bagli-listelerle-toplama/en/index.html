Add Two Numbers

You can follow every step of the solution here. Pick two lists, press Next or click Play, and see how storing the digits in reverse order makes grade-school column addition easy.

The idea in three steps

  1. 1

    Reverse order is a convenience

    The ones digit is at the head of the list. Column addition also starts from the ones digit, so walking both lists from head to tail is the same as adding from right to left.

  2. 2

    Add digit by digit

    Each round, add the two digits and the carry. sum % 10 goes into the result, and sum / 10 carries over to the next digit. A list that has run out counts as 0.

  3. 3

    Build the result behind dummy

    With an empty dummy node and a tail that points at the last node, append each digit to the end of the list. When both lists are done and no carry is left, return dummy.next.

Why is it so efficient?

O(max(m, n)) time

Each round we move one node forward in each list. The number of rounds equals the length of the longer list, plus one if there's a final carry. If the lists have lengths m and n: O(max(m, n)) time.

O(1) extra space

Apart from the result list, there are only a few variables like carry, sum and tail. The returned list is the answer itself, so it isn't counted: O(1) extra space. The nodes of the input lists aren't touched either.

Why not convert to a number?

Converting the lists to long, adding them, and converting the result back to a list is the first idea that comes to mind. But the lists can have 100 digits, while a long holds at most 19 digits; the number overflows. Adding digit by digit works no matter how long the number is.

Why is dummy there?

Without dummy, the first digit would need separate code, because while the result list is empty there's nothing to attach a node to. With a fake node at the front, every digit is added with the same two lines; at the end, dummy.next returns the real list.

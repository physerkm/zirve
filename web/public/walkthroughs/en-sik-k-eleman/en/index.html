Top K Frequent Elements

Sorting the numbers by frequency takes O(n log n). Instead, watch step by step how we build buckets whose indices represent the repeat count (frequency) and collect the k most frequent elements in exactly O(n) time.

The idea in three steps

  1. 1

    Count the frequencies

    We scan the array in a single pass and record how many times each number appears in the count dictionary.

  2. 2

    Place into frequency buckets

    A number can appear at most n times. In a buckets array of size n + 1, we put the numbers that appear f times into the list buckets[f].

  3. 3

    Collect from the highest bucket

    We walk backward from f = n, add the numbers in non-empty buckets to the result array, and stop once we reach k elements.

Why is it so efficient?

Beating the sorting bound: O(n)

Comparison-based sorts run in O(n log n) time at best. But a number's frequency has to be an integer between 1 and n. Because we know this upper bound, we can use bucket sort and reach the answer in O(n) time without any comparisons.

How does it differ from a min-heap?

Using a priority queue (min-heap) of size k takes O(n log k). When k is very small the heap is very fast too; but as k approaches n, the bucket array approach gives a clean O(n) with a small constant factor.

What if several numbers share a frequency?

Each buckets[f] cell holds a List<int>, not a single number. So all numbers with the same frequency pile up in the same bucket without colliding and are added to the result in turn.

Memory usage

Both the count dictionary and the buckets array hold at most n elements. So the extra space complexity is O(n).

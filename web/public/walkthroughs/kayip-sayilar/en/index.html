Find All Numbers Disappeared in an Array

You can follow every step of the solution here. Pick an array, press Next or click Play, and see how the box of every number we see gets marked and how the boxes left unmarked reveal the missing numbers.

The idea in three steps

  1. 1

    Every number has a box

    The numbers are between 1 and n, and the array has exactly n boxes. The box of number x is nums[x - 1]: 1's box is nums[0], 2's box is nums[1], and so on.

  2. 2

    Mark the box of each number you see

    When you see a number, make the value in its box negative. The value isn't lost, only its sign changes; when reading, you get the original number back with Math.Abs.

  3. 3

    Boxes that stay positive are missing

    If nums[i] is still positive at the end, the number i + 1 never appears in the array. While collecting, we also flip the negative boxes back to restore the array to its original state.

Why O(1) extra space?

O(n) time

We walk the array twice: first we mark the numbers we see, then we collect the boxes left unmarked. The work grows in proportion to the array length: O(n) time.

O(1) extra space

We keep the marks not in a separate array but in the sign of the numbers in nums's own boxes. The only extras are a few variables such as num, box and i: O(1) extra space. The list we return doesn't count toward this.

Why does the easier solution need more memory?

There is an easier solution too: mark the numbers you see in a bool[] seen = new bool[n + 1] array, then collect the ones left false. It also runs in O(n) time, but because it allocates a separate array of n + 1 elements it uses O(n) space. The solution on this page does the same marking inside nums, so that array isn't needed.

Why does the array return to its original state?

In the second loop we turn the negative boxes positive again. That way the calling code gets its array back exactly as it passed it in. This doesn't need a separate loop either; it happens in the same pass that collects the missing numbers.

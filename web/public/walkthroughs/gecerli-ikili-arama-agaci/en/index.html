Validate Binary Search Tree

You can follow every step of the solution here. Pick a tree, press Next or click Play, and see how the (low, high) range carried down to each node catches the invalid ones.

The idea in three steps

  1. 1

    Checking only the parent is not enough

    Say the root is 5, its right child is 6, and 6's left child is 3: since 3 < 6 it satisfies the local rule, but because it sits in 5's right subtree it must actually be greater than 5.

  2. 2

    Carry an open range to every node

    The root starts with the range (-∞, +∞). Going left, the upper bound becomes the node's value (low, node.val); going right, the lower bound does (node.val, high).

  3. 3

    Guard the bounds with long

    Since a node value can be int.MinValue or int.MaxValue, we set the initial bounds to long.MinValue and long.MaxValue; on equality (<= or >=) we return false immediately.

    Why is it so efficient?

    O(n) time, O(h) space

    Each node is visited exactly once, and each visit does only two number comparisons: O(n) time. The recursion stack grows at most to the tree's height h: O(log n) for a balanced tree, O(n) space for a tree that extends down a single branch.

    Why long.MinValue and long.MaxValue?

    According to the constraints, a node value can be -2³¹ (int.MinValue) or 2³¹ - 1 (int.MaxValue). If we kept the bounds as int, a valid single-node tree with value int.MinValue would fail the node.val <= low check and wrongly return false.

    The short-circuit (&&) advantage

    In the expression IsValid(node.left, ...) && IsValid(node.right, ...), as soon as the left subtree returns false, C# never enters the right subtree. The search stops the moment an error is found.

    Alternative: inorder traversal

    If you traverse a BST in left–root–right (inorder) order, the values come out in strictly increasing order. Keeping the previous value and checking node.val <= prev also works, with the same O(n) time and O(h) space complexity.

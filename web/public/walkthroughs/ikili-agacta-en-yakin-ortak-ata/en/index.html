Lowest Common Ancestor of a Binary Tree

Step through how we find the lowest common ancestor (LCA) of nodes p and q in an unordered binary tree with a single DFS pass that carries information from the bottom up.

The idea in three steps

  1. 1

    Stop when you hit a target

    If the node we reach is null or its value equals p or q, we don't go any deeper; we return that node upward right away.

  2. 2

    Ask the left and right subtrees

    Recursively, we find out whether either target is in the left (left) or right (right) subtree.

  3. 3

    If both sides are non-null, it's the meeting point

    If both left and right come back non-null, the targets meet for the first time at this node (the LCA). If only one side is non-null, we pass it upward.

Why is it so efficient?

O(n) time in a single pass

Instead of recording the root-to-target paths separately and comparing them, a single DFS does both the searching and the merging. Each node is visited at most once: O(n) time and O(h) space for the call stack.

Why is the early return correct?

In Example 2 (p=5, q=4), when we reach node 5, we return 5 immediately without searching for the 4 below it. If 4 is in 5's subtree, the common ancestor is 5 anyway; if 4 is on another branch, the branches of 5 and 4 will meet at a node higher up.

Information carried upward

The line return left ?? right; handles two different jobs in one expression: if only one target has been found so far, it carries that target's reference upward; if the LCA was already found in a subtree, it passes the LCA itself all the way up to the root unchanged.

How is it different from a BST?

In a binary search tree (LeetCode 235), we can look at the node values, descend into just one branch, and solve it in O(h) time. A plain binary tree has no ordering property, so we must query both subtrees.

Missing Number

You can follow every step of the solution here. Pick an array, press Next or click Play; see how the array's sum builds up and how its difference from the expected sum gives the missing number.

The idea in three steps

  1. 1

    What would the sum be if nothing were missing?

    If the array has length n, the numbers are between 0 and n. If all of them were there, the sum would be 0 + 1 + … + n. There is no need to add these up in a loop; there is a formula: n * (n + 1) / 2.

  2. 2

    Add up the numbers in the array

    We walk the array once and add each element to actualSum. There is no need to record separately which numbers we have seen.

  3. 3

    The difference is the missing number itself

    Every number except the missing one appears in both sums, so they cancel out when you subtract. What remains, expectedSum - actualSum, is the missing number.

Why O(n) time and O(1) space?

O(n) time

We walk the array only once. The expected sum comes from the formula in a single operation, with no loop. The work grows in proportion to the array's length: O(n) time.

O(1) space

No matter how many elements the array has, we keep only four variables: n, expectedSum, actualSum, and num. There is no array or set recording which numbers we have seen: O(1) space.

Where does the formula come from?

Write the numbers from 0 to n once in order and once in reverse, one row under the other. Each column adds up to n, and there are n + 1 columns. The two rows together add up to n · (n + 1). Since we counted every number twice, we divide by 2.

0 + 1 + 2 + 3 + 3 + 2 + 1 + 0 ─────────────── 3 + 3 + 3 + 3 = 3 · 4 = 12 12 / 2 = 6

Can it overflow?

An int can hold at most 2,147,483,647. In this problem n is at most 10,000, so the expected sum is at most 50,005,000; it fits easily. If n were 46,341 or larger, the product n * (n + 1) would not fit in an int and you would need a long.

What if the missing number is 0?

0 adds nothing to a sum. If 0 is missing, the two sums come out equal and the difference is 0; the answer is still correct. For example [3, 1, 2]: 6 − 6 = 0. You can follow it in the preset examples above.

Other approaches

Sorting the array and looking for the spot where the numbers shift also works, but sorting takes O(n log n). Marking the seen numbers with a HashSet or a bool[] runs in O(n) time but needs O(n) space. XOR also solves it in O(n) time and O(1) space, but the sum method is shorter and easier to read.

Permutations

You can follow every step of the solution here. Pick the numbers, press Next or click Play. See step by step which branch of the decision tree is being explored, how current and used change, and how the permutations are added to result.

The idea in three steps

  1. 1

    Choose

    Pick a number not used yet for the next slot. Add it to current and mark it as "used" in used.

  2. 2

    Explore

    Backtrack calls itself to fill the next slot. When all slots are full, a copy of the list as it is at that moment is added to result.

  3. 3

    Undo

    When the call returns, remove the last number from the list and clear its mark. Everything goes back to how it was before the choice. The loop then tries the next number for the same slot.

    Why O(n · n!) time and O(n) space?

    O(n · n!) time

    n distinct numbers have n! permutations, so the bottom row of the tree has n! leaves. At each leaf, a copy of the n-number list is made: n · n! work. The other circles in the tree add up to at most about 1.72 times the number of leaves, and each runs an n-step for loop. The total is still O(n · n!) time.

    O(n) extra space

    current holds at most n numbers, and used has n slots. At most n + 1 Backtrack calls are open at the same time: one per slot, plus the one that sees the list is full. The result list holds n · n! numbers, but since the problem asks for it anyway, it's usually not counted: O(n) extra space.

    Why do we add a copy?

    current is a single list shared by all calls. If you write result.Add(current), result doesn't get six separate lists; it gets six references pointing to the same list. The undo steps eventually empty that list, and the result looks like this:

    [[], [], [], [], [], []]

    new List<int>(current), on the other hand, takes a snapshot of the list as it is at that moment. Even if current changes later, the copy doesn't.

    What if there were no undo?

    If you delete the two undo lines, only the first permutation is found. After [1, 2, 3], every slot of used stays true and no call can pick a new number. Undoing restores everything to how it was before the choice once a branch is finished. That way the next number can be tried for the same slot. This is where the method gets its name: backtracking, meaning choose, explore the branch, go back.

    Without used: by swapping

    Another common solution arranges the numbers by swapping them inside the array. The slots before start count as filled. Each number in turn is brought into the start slot, and the swap is undone when the child call finishes. You don't need used or current, and the time is still O(n · n!). But nums gets shuffled while it runs, and the code is harder to follow. That's why the solution uses the version with used.

    private static void Backtrack(int[] nums, int start,
    List<IList<int>> result)
{
    if (start == nums.Length)
    {
        result.Add(new List<int>(nums));
        return;
    }

    for (int i = start; i < nums.Length; i++)
    {
        (nums[start], nums[i]) = (nums[i], nums[start]);  // choose
        Backtrack(nums, start + 1, result);                // explore
        (nums[start], nums[i]) = (nums[i], nums[start]);  // undo
    }
}

    Can it be faster?

    No. The answer itself is n! lists with n numbers each; just writing them out takes n · n! steps. Since this solution finds each permutation exactly once, it sits at that bound. n! grows very fast: 3 numbers mean 6 permutations, 6 numbers 720, 10 numbers 3,628,800. That's why LeetCode gives at most 6 numbers. The same choose → explore → undo pattern is also used in problems like Subsets (78), Combination Sum (39), and N-Queens (51).

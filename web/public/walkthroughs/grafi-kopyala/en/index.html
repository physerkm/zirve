Clone Graph

Step through how the oldToNew dictionary prevents an infinite loop while you clone a graph with cycles, and how it wires neighbor references to the new copy nodes.

The idea in three steps

  1. 1

    Keep an old → new mapping

    Dictionary<Node, Node> oldToNew maps every original node to its own new copy. That way, each node is copied at most once.

  2. 2

    Register in the dictionary first, then explore

    As soon as you create the new node, and before visiting its neighbors, you must set oldToNew[node] = copy; otherwise cycles cause infinite recursion.

  3. 3

    Link neighbors recursively

    For each neighbor, call copy.neighbors.Add(Dfs(nei)): if the neighbor was already cloned, its existing copy comes back from the dictionary; if not, a new one is created.

Why O(V + E)?

Each node is created exactly once

The first time a node is visited, it is added to the oldToNew dictionary. On every later encounter, TryGetValue returns the existing copy in O(1), so the subgraph is never explored again.

Why don't undirected edges cause trouble?

On the edge 1 — 2, when you move from 1 to 2, 1 is already in the dictionary. When 2 looks at its neighbor 1, it gets the copy 1' from the dictionary and returns immediately.

Deep copy vs. shallow copy

In a shallow copy, the new list points to the old Node objects. In a deep copy, new Node(node.val) is called for every node, allocating brand-new objects in memory.

Can you do it with BFS too?

Yes! With a queue (Queue<Node>) and the same oldToNew dictionary, a BFS solution has exactly the same O(V + E) time and O(V) space complexity.

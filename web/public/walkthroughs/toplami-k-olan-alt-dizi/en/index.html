Subarray Sum Equals K

In this problem a sliding window fails because of negative numbers. Watch how counting prefix sums in a Dictionary gets you an O(n) solution in a single pass.

The idea in three steps

  1. 1

    Maintain the prefix sum

    Keep the sum from the start of the array up to the current element in curSum. The difference of two prefix sums gives the sum of the subarray between them.

  2. 2

    How many times has curSum − k been seen before?

    When the current sum is curSum, every earlier point where you saw the sum curSum - k starts a subarray that ends at the current element and sums to k.

  3. 3

    Record the frequency in the table

    Because of negative and zero elements, the same prefix sum can occur more than once. Start the table with {0: 1} and increment the frequency of curSum at every step.

Why is it so efficient?

Why doesn't a sliding window work?

A sliding window (two pointers) works on arrays where the sum strictly grows as the right pointer advances (all numbers are positive). When the array contains -3 or 0, shrinking the window can increase the sum and make you miss valid subarrays.

What is the initial {0: 1} for?

When a subarray starting at the very beginning (index 0) sums to exactly k, curSum = k and curSum - k = 0. Putting 0: 1 in the dictionary up front counts these subarrays automatically, with no extra if (curSum == k) check.

Why keep a frequency instead of just present/absent?

In the [1, -1, 0] example, the prefix sum 0 occurs more than once. When curSum - k = 0 is looked up later, every earlier 0 point means a different start index; that is why you need a Dictionary that keeps frequencies rather than a HashSet.

Query first, then insert

In the loop, curSum - k is queried first, and only then is the current curSum added to the dictionary. If the order were reversed, with k = 0 the lookup curSum - 0 = curSum would match itself and wrongly count the empty subarray.

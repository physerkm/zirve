Valid Anagram

You can follow every step of the solution here. Pick two words, press Next or click Play, and see how all the counters meet at zero when we increment them for the letters in s and decrement them for the letters in t.

The idea in three steps

  1. 1

    Check the lengths first

    If the two words have different numbers of letters, they can't be anagrams of each other. If s.Length != t.Length, we return false without entering the loop at all.

  2. 2

    s increments, t decrements

    In the 26-element counts array, at each step i we increment the counter for letter s[i] by 1 and decrement the counter for letter t[i] by 1.

  3. 3

    Are they all zero?

    If every letter appears the same number of times in both words, the increments and decrements cancel out exactly: counts.All(count => count == 0).

Step through it

Type 1 to 12 lowercase English letters (a-z) only.

s (counts[s[i] - 'a']++)

t (counts[t[i] - 'a']--)

counts[26] (current counters for the letters in the words)

> 0 (more in s) < 0 (more in t) = 0 (balanced)

Why is it so efficient?

O(n) time, O(1) memory

No matter how long the strings are (say, 50,000 characters), the counts array always holds a fixed 26 integers: O(1) extra space. Since the single loop looks at each index once, the time complexity is O(n).

How does char - 'a' become an index?

In the ASCII table, lowercase English letters are consecutive: 'a' - 'a' = 0, 'b' - 'a' = 1, …, 'z' - 'a' = 25. So we access the array index directly, with no hash computation needed.

What if there were Unicode characters?

If the input contained Turkish letters, emojis, or the full Unicode set, a fixed 26-element array wouldn't be enough; we would use a Dictionary<char, int>. The time would still be O(n), and the space would grow with the number of unique characters.

How does it compare to sorting?

Converting both strings to character arrays, sorting them, and comparing also gives the right answer, but sorting costs O(n log n) time and O(n) memory for the copied arrays. Frequency counting is both faster and uses less memory.

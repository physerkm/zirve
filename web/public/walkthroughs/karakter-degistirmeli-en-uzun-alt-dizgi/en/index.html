Longest Repeating Character Replacement

How many replacements does it take to turn a window into a single letter? windowSize - maxFreq. When that difference exceeds k, we slide the window one position from the left, finding the longest substring in O(n) time.

The idea in three steps

  1. 1

    Keep the majority letter

    Keeping the most frequent letter in the window (maxFreq) fixed and turning every other letter into it always needs the fewest replacements.

  2. 2

    Slide if the difference exceeds k

    When (right - left + 1) - maxFreq > k, the window is invalid; we decrement the count of s[left] and slide the window with left++.

  3. 3

    No need to decrease maxFreq

    A longer valid window is only possible with a larger maxFreq, so we don't rescan maxFreq as the window shrinks.

Why is it so efficient?

Why is a single if enough instead of a while?

At each step, right grows by only 1. When the window is invalid, also incrementing left by 1 keeps the window size constant. Since our goal is to beat the largest size, shrinking the window further brings no benefit.

Why is maxFreq never decreased?

When the left character leaves, the true maximum frequency may drop; but to get a larger best, we need a new frequency that beats the previous maxFreq anyway. This saves us from rescanning all 26 letters.

Time and space complexity

The right and left pointers each scan the string at most once: O(n) time. The frequency array has a fixed size of 26, so it uses O(1) extra space.

What would brute force do?

Trying every substring and finding the most frequent letter in each would take O(n²). The sliding window updates the same information step by step instead of recomputing it from scratch.

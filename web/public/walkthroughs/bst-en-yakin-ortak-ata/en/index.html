Lowest Common Ancestor of a Binary Search Tree

Use the BST property to find the first node where the paths to p and q split, following a single path down from the root instead of scanning the whole tree.

The idea in three steps

  1. 1

    Both smaller: go left

    If both p and q are smaller than the current node's curr.val, both are in the left subtree; we rule out the right branch entirely.

  2. 2

    Both larger: go right

    If both p and q are larger than the current node's curr.val, both are in the right subtree; we rule out the left branch entirely.

  3. 3

    The first split point is the LCA

    If one is on the left and the other on the right (or one of them equals curr), the paths split right here; the lowest common ancestor we want is curr.val.

Why is it so efficient?

Each step rules out a subtree

In an ordinary binary tree, finding the common ancestor means recursively scanning both the left and right subtrees (O(n)). In a BST, comparing with curr.val tells us exactly which way to go, and we leave one level behind at each step: O(h) time.

O(1) extra space

There's never a need to go back and try another branch, so no call stack (recursion stack) is needed. Walking down from the root with a single curr reference runs in O(1) space.

When a node is its own ancestor

In Example 2 with p = 2, q = 4, when we reach node curr = 2, the condition p < 2 fails, so we go straight into the else branch and return 2. No extra equality check is needed.

Why can't there be a deeper common ancestor?

Once p and q fall on two different sides of a node, going left loses q and going right loses p. So the first node where they split is a common ancestor, and also the deepest one possible.

Encode and Decode Strings

When the strings can contain #, digits, or spaces, a simple delimiter does not work. Pack each string as <length>#<string> and step through both the encode and the decode phases.

The idea in three steps

  1. 1

    Add a length + '#' prefix

    We write the character count and a # in front of each string: for example, the string "a#b" is packed as "3#a#b".

  2. 2

    When decoding, find the '#' first

    Starting at position i, we find the index j of the first # character. s[i..j] gives us the exact length of the string (length).

  3. 3

    Read exactly 'length' characters

    Starting at position j + 1, we cut out exactly length characters; even if a # appears inside, it is not mistaken for a delimiter.

Why is it so efficient?

Why is escaping more complicated?

You could also encode delimiters with escape characters such as \# and \\, but that requires checking every character one by one. With the length-prefix method, once length is read, the whole block is taken at once with Substring(start, length).

Why do we need both the length and the '#'?

If we wrote only the length, the string "9999" of length 4 would become "49999", and when decoding we could not tell whether the length is 4 or 49999. The # marks exactly where the length number ends.

How is the empty string ("") told apart?

An empty string is encoded as "0#". When decoding, length = 0 is read and "" is added to the list. That way the empty array [] (encoded as "") and [""] (encoded as "0#") never get mixed up.

Time and Space Complexity

Each character is processed a constant number of times in both the Encode and Decode phases: total time is O(N), and extra space beyond the output is O(1).

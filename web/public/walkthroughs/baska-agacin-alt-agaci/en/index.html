Subtree of Another Tree

Follow step by step how each node of the main tree is treated as a potential root and checked with IsSameTree for an exact match with the subRoot tree.

The idea in three steps

  1. 1

    Every node is a candidate root

    IsSubtree walks the main tree and asks every root node it visits: "does the subtree we're looking for start right here?"

  2. 2

    Compare the two trees exactly

    IsSameTree(a, b) checks the values and children of two nodes in lockstep. It rejects the match if there's even one extra leaf.

  3. 3

    If not, go down the branches

    If the current node doesn't match, the search isn't over; the branches below are searched with IsSubtree(root.left, subRoot) || IsSubtree(root.right, subRoot).

Why is it so efficient?

Early exit (short-circuit)

As soon as the root values differ (for example 3 != 4), IsSameTree returns false in O(1) steps without going down to the children. So in practice, a deep comparison only happens at nodes whose value equals subRoot.val.

Mind the definition of a subtree

A subtree is a node together with all of its descendants. In Example 2, the values 4, 1, 2 are present, but there's a 0 under 2, so the IsSameTree(null, 0) check catches it and prevents a false match.

Time and space complexity

If the main tree has n nodes and the subtree has m, the worst case takes O(n · m) time. The call stack depends on the heights and uses O(hn + hm) extra space.

Why is it safe with duplicate values?

In the example root = [1, 1] and subRoot = [1], if we stopped at the first 1 node and trusted only the IsSameTree result, we would return false. But because we keep going down into the left and right subtrees after a failed attempt, the 1 at the leaf is found.

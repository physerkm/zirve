Number of Islands

You can follow every step of the solution here. Pick a grid, press Next or click Play, and see how each island you find gets sunk with Sink (DFS) and how that keeps the same island from being counted twice.

The idea in three steps

  1. 1

    Scan the grid row by row

    We look at each cell in turn. If the cell is '0' (water), we skip it without doing anything.

  2. 2

    Found land? Increment the counter

    If the cell is '1', we have set foot on a new island for the first time, so we do count++.

  3. 3

    Sink the whole island (DFS)

    With the Sink method we turn that cell and all of its horizontally/vertically connected '1' neighbors into '0'. That way, as the loop moves on, it doesn't mistake other parts of the same island for a new island.

Why is it so efficient?

Each cell is visited a constant number of times: O(R × C)

Two nested for loops with a recursive Sink inside may look slower at first glance. But a land cell turns from '1' into '0' only once and never enters Sink again. The total work is O(rows × columns).

Marking without an extra visited array

Because we mark visited land cells directly by setting grid[row][col] = '0', there is no need to allocate a separate bool[,] visited matrix. Only call stack space is used.

Why don't diagonal neighbors count?

By the problem definition, only the 4 directions (down, up, right, left) count as neighbors. Two diagonally adjacent '1's are not connected; that is why the "Diagonals" preset produces 5 separate islands.

What if we can't modify the input?

If the interviewer says you may not modify the input, either keep a visited array or temporarily set cells to '#' and turn them back into '1' at the end.

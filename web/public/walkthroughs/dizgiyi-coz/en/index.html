Decode String

Step through how we decode nested k[encoded_string] blocks in a single left-to-right pass using two stacks (countStack and stringStack).

The idea in three steps

  1. 1

    Accumulate numbers and letters

    Each time you see a digit, build the repeat count with k = k * 10 + d; append ordinary letters directly to the current string.

  2. 2

    On [, save the context on the stacks

    An opening bracket starts a new inner block. Push the current k and current values onto the stacks and reset them for the new block.

  3. 3

    On ], expand the inner block and join

    At a closing bracket, pop the last repeat count (repeat) and the outer string (prev) from the stacks; append current to the end of prev repeat times.

Why is it so efficient?

Why do we use two stacks?

When we see a [, we need to remember both how many times that block repeats (k) and which string had accumulated before it (current). Two separate stacks keep both pieces of information in LIFO (last in, first out) order, without type conversions or complicated parsing.

How are multi-digit numbers handled?

A repeat count can have several digits, as in 10[a] or 100[b]. Because we do k = k * 10 + (ch - '0') for every digit, the whole number is ready in k by the time we reach the [ character.

How is it different from recursion?

The same logic can be written as a recursive function; then the call stack takes over the job of our countStack and stringStack. Using an explicit stack removes the risk of a stack overflow on deeply nested expressions.

Time and space complexity

Each character of the input string is processed exactly once, and at every closing ] the inner string is copied as many times as the repeat count. If the output string has length M, the total running time and memory use are O(M).

Sort Colors

You can follow every step of the solution here. Pick an array, press Next or click Play, and watch how the 0s are sent to the left, the 2s to the right, and how the 1s gather in the middle on their own.

This method is called the Dutch national flag algorithm. It is named after the red, white and blue striped Dutch flag that Edsger Dijkstra used when he described the problem.

The idea in three steps

  1. 1

    Think of the array as four regions

    From left to right: 0s, 1s, boxes not yet examined, 2s. Three variables hold the boundaries: low is the first box after the 0s, mid is the box being examined now, high is the last unexamined box.

  2. 2

    Send 0 left, 2 right

    If nums[mid] is 0, it swaps with the box at low; if it is 2, it swaps with the box at high. If it is 1, it already sits at the end of the 1s, so only mid moves forward by one.

  3. 3

    Recheck what comes from the right

    When you send a 2 to the right, you haven't examined the box that comes back yet, so mid stays put. Once no unexamined boxes are left (mid > high), the array is sorted.

Why O(n) time and O(1) memory?

O(n) time

In every iteration either mid moves one to the right or high moves one to the left. So the unexamined region shrinks by exactly one box per iteration. Since it starts with n boxes, the loop runs exactly n times, with a few operations each time: O(n) time. We traverse the array only once; that is the "one pass" LeetCode asks for in the follow-up.

O(1) memory

No matter how large the array is, we keep only three variables: low, mid and high. We don't copy the boxes into a new array; we swap them inside nums: O(1) memory.

Why doesn't mid advance after a 2?

The box that comes from high comes from the unexamined region; it could be a 0 or a 2. In [1, 2, 0], the 2 swaps with the last 0 and the array becomes [1, 0, 2]. If mid advanced at this point, the loop would end and the 0 would stay in the wrong place. If it stays put, it sees the 0 in the next iteration and sends it to the left.

Why can mid advance after a 0?

There are only 1s between low and mid, because we have already examined those boxes. When you send the 0 to low, the box that comes back is a 1 and lands at the end of the 1s. If low and mid point to the same box, the 0 swaps with itself. Either way, no new box needs examining, so both can advance.

How is it different from the counting solution?

Counting how many of each color there are and then rewriting the array is also a correct solution; it also uses O(n) time and O(1) memory. The difference is that it traverses the array twice. Also, counting writes new values into the boxes, while this solution moves the existing boxes around. If the boxes held numbered balls instead of plain numbers, counting and rewriting would lose the balls; swapping would still work.

What does (a, b) = (b, a) do?

It swaps the values of two boxes. C# first reads the two values on the right, then writes them into the two boxes on the left. So both change at once and no value is lost. You can do the same thing in three lines with a temporary variable: first copy one into temp, then write the other in its place, and finally put temp in the other's place.

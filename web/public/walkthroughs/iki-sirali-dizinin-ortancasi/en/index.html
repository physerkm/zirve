Median of Two Sorted Arrays

Step through how we find the right partition line (i and j) without merging the two sorted arrays, by running a binary search on the shorter array.

The idea in three steps

  1. 1

    The median is a partition line

    The left half of the merged array must contain half = (m + n + 1) / 2 elements in total. If we take i elements from the first array, we must take j = half - i elements from the second.

  2. 2

    Compare the cross boundaries

    Since each array is sorted on its own, we only compare the largest values to the left of the cut with the smallest values to its right: maxLeftA ≤ minRightB and maxLeftB ≤ minRightA.

  3. 3

    Binary search on the shorter array

    If maxLeftA > minRightB, i is too large (move left); if maxLeftB > minRightA, i is too small (move right). The search range halves at every step.

Why is it so efficient?

O(log(min(m, n))) time

Merging the arrays would take O(m + n). Instead, we only binary search for the cut point in the shorter array. Even with two arrays of 1000 elements, the median is found in at most 10 steps.

Why do we search the shorter array?

If we searched the longer array, the computed j = half - i could fall outside the bounds of the shorter array (negative or greater than m). When 0 ≤ i ≤ m is chosen in the shorter array, 0 ≤ j ≤ n is always guaranteed.

What are the -∞ and +∞ boundaries for?

When the cut line lands at the very start (i = 0) or the very end (i = m) of an array, there are no elements left on that side. Treating the left boundary as int.MinValue and the right boundary as int.MaxValue removes extra if branches.

O(1) extra space

We don't create a new array; we only keep a few boundary indices (left, right, i, j), so memory usage is constant.

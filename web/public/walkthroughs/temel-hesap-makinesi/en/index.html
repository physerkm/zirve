Basic Calculator

In an expression with no multiplication or division, you can think of every subtraction as setting the sign of the next term to -1. When a parenthesis opens, push the current total and sign onto the stack and start from zero; when it closes, restore them from the stack.

The idea in three steps

  1. 1

    Carry the sign to the number

    Keep result (the running total), number (the number being read) and sign (+1 or -1). When you see an operator, do result += sign * number.

  2. 2

    Save to the stack on an opening parenthesis

    When '(' arrives, push the result so far and the sign in front of the parenthesis onto the stack; reset both for the new parenthesized part.

  3. 3

    Combine on a closing parenthesis

    When ')' arrives, first multiply the result inside the parentheses by the sign on the stack, then add the previous subtotal from the stack.

Why is it so efficient?

O(n) time in a single pass

Each character is read only once. Instead of copying parenthesized parts as substrings or using recursion, pushing and popping two integers (result and sign) takes O(1).

How does unary minus just work?

In expressions like "- (3 + 4)" or "1 - (-2)", number is already 0 when '-' arrives. result += sign * 0 leaves the total unchanged, and sign is set to -1.

Why push both result and sign onto the stack?

When a parenthesis opens, there is a subtotal waiting outside (result) and a sign that will multiply the whole result of the parentheses (sign). Pushing both onto the stack in order makes it easy, when the parenthesis closes, to first multiply by the sign and then add to the previous total.

Why is the addition after the loop needed?

If the expression ends with a number rather than a parenthesis (for example "2 - 1 + 2"), no operator follows the last number, so it is never added to result inside the loop. return result + sign * number accounts for this last term.

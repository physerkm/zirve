Subsets II

How do we find all subsets of an array with repeated elements without generating duplicate subsets? Watch step by step how we sort the array and prune duplicates on the same level with the rule i > start && nums[i] == nums[i - 1].

The idea in three steps

  1. 1

    Sort the array first

    Array.Sort(nums) puts equal elements next to each other, so we can check in O(1) whether a number equals the previous one.

  2. 2

    Add every node to the result

    Every path in the decision tree is a valid subset. As soon as we enter the function, we save a copy of the current path to the result list.

  3. 3

    Skip duplicates on the same level

    If i > start && nums[i] == nums[i - 1] within the same for loop, we have already tried this number at this position, so we skip it with continue.

Why is it so efficient?

i > start vs. i == start

When i == start, we are looking at the first element of a new depth level; for example, adding the second 2 on top of [1, 2] to make [1, 2, 2] is perfectly valid. But when i > start, we are trying to remove the first 2 on the same level and put the second 2 in its place, which would generate the subset [1, 2] a second time.

Why is this better than using a HashSet?

You could also generate every subset and filter out duplicates with a set (HashSet), but that approach still walks every duplicate subtree to the end, doing unnecessary exponential work. Pruning a branch right at its start skips the whole duplicate subtree without ever building it.

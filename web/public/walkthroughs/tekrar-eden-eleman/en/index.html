Contains Duplicate

You can follow every step of the solution here. Pick an array, press Next or click Play, and see how HashSet.Add catches a duplicate by checking and adding in a single move.

The idea in three steps

  1. 1

    Keep what you've seen in a set

    A HashSet<int> holds each number at most once and answers "have we seen this number before?" in O(1) time.

  2. 2

    Check and add with Add

    seen.Add(n) adds the number and returns true if it isn't in the set; if it is already there, it returns false without changing the set.

  3. 3

    Exit at the first duplicate

    As soon as the condition !seen.Add(n) holds, we return true without looking at the rest of the array. If the loop finishes, no number was repeated: false.

Why is it so efficient?

O(n) time and early exit

Each element costs a single HashSet.Add call, which takes O(1) on average. What's more, if the duplicate is caught at the start of the array (for example [1, 1, ...]), we exit at the second step without ever looking at the thousands of remaining elements.

Why a single Add instead of Contains + Add?

Calling seen.Contains(n) and then seen.Add(n) searches the same hash table twice. In C#, HashSet.Add already returns a bool telling you whether the element was there before, so a single lookup does the job.

Comparison with sorting

If we sort the array, duplicate numbers end up next to each other and the problem can be solved without extra memory, in O(1) space; but sorting takes O(n log n) time and modifies the input array. If memory isn't constrained, HashSet is faster.

Why is brute force slow?

Comparing each element with every element after it takes O(n²). For an array of 100,000 elements, that is about 5 billion comparisons; HashSet finishes in at most 100,000 steps.

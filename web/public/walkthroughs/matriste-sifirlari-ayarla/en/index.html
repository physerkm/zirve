Set Matrix Zeroes

Follow step by step how the zeroing is done with O(1) extra memory, without allocating extra arrays, by using the matrix's own first row and first column as markers.

The idea in three steps

  1. 1

    Use the first row and column as markers

    Every time you see a 0, set matrix[0][c] = 0 and matrix[r][0] = 0. Keep the first row's own marker in the firstRowZero variable so they don't collide.

  2. 2

    Zero the inner cells first

    Walk the inner region starting from (1, 1); if the row's head (matrix[r][0]) or the column's head (matrix[0][c]) is zero, zero the cell.

  3. 3

    Zero the edges last

    Once the inner cells are done, first zero column 0 if matrix[0][0] == 0, then zero row 0 if firstRowZero is true.

Why is it so efficient?

Why O(1) extra memory?

Normally, keeping track of which rows and columns to zero in bool[m] and bool[n] arrays costs O(m + n) memory. Writing 0 into the first cell of a row or column that will be zeroed anyway loses no data; that way the matrix becomes its own marker array.

Why is firstRowZero required?

The cell matrix[0][0] is the head of both row 0 and column 0. If we kept both in a single cell, a zero in column 0 would wrongly zero row 0 as well. firstRowZero resolves this collision with a single bool.

Why the inner region first, then the first column, and the first row last?

If we zeroed row 0 and column 0 early, we would overwrite the markers the inner cells rely on. Likewise, if we zeroed row 0 before column 0, we would corrupt the matrix[0][0] marker.

Time complexity

Each cell is visited at most twice (once in the marking phase, once in the update phase). The total running time is exactly O(m · n).
